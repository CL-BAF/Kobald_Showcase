# Public Project History

This is a short public history of Kobald milestones represented in the showcase repository. It is not a complete development changelog for the private codebase.

## July 2026

### Public showcase published

The Kobald showcase was published with an overview of the project's evidence focused design, human review model and local AI direction.

### v0.8.0 baseline documented

The public project documentation identifies v0.8.0 as a tagged baseline with:

- 295 automated tests passing
- 1 test skipped
- deterministic offline demonstration capability
- evidence provenance and review workflow foundations

### v0.9.0 release candidate documented

The next public development candidate expanded the model provider layer and associated safety controls.

The currently documented candidate reports:

- 604 automated tests passing
- 1 skipped opt in live smoke test
- bounded local, mock and consent gated cloud provider support
- source linked response validation
- metadata oriented audit behaviour

The release candidate status is intentionally described as development work rather than a finished production release.

## September 2026

### Command Centre added to the showcase

Public screenshots were added for the early Kobald Command Centre, settings and diagnostics interfaces.

The screenshots are labelled as development builds so that interface progress is visible without presenting unfinished software as a completed product.

### Public compute roadmap expanded

The showcase was expanded to explain why larger local AI compute matters to the project, including local models, multimodal work, longer running agent workflows and later model adaptation experiments.

### Sponsorship and technical review material added

The public repository was expanded with:

- a high level architecture overview
- a testing and verification explanation
- an NVIDIA DGX Spark development plan
- a clearer distinction between the public showcase and the private implementation

## Documentation principle

Kobald's public history intentionally separates three things:

1. what is implemented now
2. what has been tested as development work
3. what remains a future target

That separation is important because the purpose of the showcase is to make project progress understandable without overstating capability or publishing the complete private codebase.
